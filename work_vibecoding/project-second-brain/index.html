Case study

From problem to working product

The Second Brain is a typed Markdown knowledge graph embedded inside a project repository. It gives coding agents a route-before-read recall loop, atomic knowledge nodes, typed edges, lifecycle rules, operating logs, and a portable handoff path that works through files and git.

The problem

Long-running AI-assisted projects repeatedly lose context: decisions are re-litigated, constraints drift, one agent cannot see another agent's reasoning, and transcripts become too large to act as dependable memory.

The response

Durable knowledge is captured as small typed nodes with summaries, provenance, confidence, status, and explicit graph relationships. Agents route through frontmatter before opening bodies, update active task state before handoff, and preserve history instead of silently overwriting prior decisions.

Workflow

How the system moves

01

Route

Read summaries, tags, and edges first so recall is targeted instead of transcript-wide.

02

Decide

Follow relevant nodes, inspect evidence, and make contradictions or superseding decisions explicit.

03

Remember

Write durable learnings as atomic nodes, update task state, append the operation log, and commit the handoff.

Build decisions

Choices that shaped the product

  • Keep each project's memory isolated inside its own repository.
  • Use plain files and git as the portable core so memory is not tied to one agent vendor.
  • Preserve lifecycle history by archiving and superseding nodes instead of mutating away old context.

What it demonstrates

Proof beyond the interface

  • Design of practical long-horizon memory for AI-assisted software work.
  • Information architecture that makes provenance, confidence, and task state inspectable.
  • Operational discipline around handoff, rollback, isolation, and secret safety.
